02

What it tests

People type a surprising number of yes/no questions into search engines ('is france the same timezone as the uk'). BoolQ collects those and pairs each with the Wikipedia paragraph a human used to answer it.

The questions look trivial but the answers require inference: the passage rarely says 'yes' or 'no' explicitly, so the model has to compare what is asked with what is stated, handle hedges, and sometimes do a bit of world knowledge.

Majority class (yes) is about 62%, which is why early models looked better than they were. GPT-3 few-shot reached 76.4%, well below fine-tuned models.

Quickstart

Load the benchmark and score a Hugging Face causal LM on it in a few lines.

1Install
shell
pip install -U datasets transformers evaluate lm-eval sacrebleu rouge-score scikit-learn
2Load the data

question, passage, label (0 no · 1 yes). Also available as `google/boolq` with boolean `answer`.

python · load
from datasets import load_dataset

ds = load_dataset("aps/super_glue", "boolq", split="validation")
print(ds)            # columns: question, passage, label (0 no · 1 yes)
print(ds[0])
3Score a model

Two helpers cover every benchmark in this collection: loglik for anything multiple-choice (score each option, pick the highest) and generate for anything free-form. Swap MODEL for whatever you are evaluating.

python · helpers
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

MODEL = "gpt2"                                   # or "Qwen/Qwen2.5-1.5B", "meta-llama/Llama-3.2-1B", …
tok = AutoTokenizer.from_pretrained(MODEL); model = AutoModelForCausalLM.from_pretrained(MODEL, torch_dtype=torch.bfloat16).eval().to("cuda")

@torch.no_grad()
def loglik(context, continuation):
    """Sum of log-probs of `continuation` tokens given `context` — the standard multiple-choice scorer."""
    ids = tok(context + continuation, return_tensors="pt").input_ids.to(model.device)
    n_ctx = len(tok(context).input_ids)
    logp = model(ids).logits.log_softmax(-1)[0, :-1]
    return logp.gather(1, ids[0, 1:, None])[n_ctx - 1:].sum().item()

@torch.no_grad()
def generate(prompt, max_new_tokens=32, stop=None):
    ids = tok(prompt, return_tensors="pt").input_ids.to(model.device)
    out = model.generate(ids, max_new_tokens=max_new_tokens, do_sample=False, pad_token_id=tok.eos_token_id)
    text = tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True)
    return text.split(stop)[0] if stop else text
python · evaluate
def prompt(ex): return f"{ex[&#x27;passage']}\nQuestion: {ex['question']}?\nAnswer:"
acc = sum(int((loglik(prompt(ex), " yes") > loglik(prompt(ex), " no")) == bool(ex["label"])) for ex in ds) / len(ds)
print("accuracy", acc)
4Or use lm-evaluation-harness

Task name(s): boolq. The harness reproduces the GPT-3 prompt formats and reports the standard metric.

shell
lm_eval --model hf --model_args pretrained=gpt2,dtype=bfloat16 \
        --tasks boolq --num_fewshot 0 --batch_size auto --output_path results/
07

Pitfalls

  • Always compare to the 62% majority baseline.
  • Questions are lower-case and un-punctuated search queries; do not 'clean' them, that is the task.
  • lm-eval scores log P('yes') vs log P('no') after the passage; a chat-style prompt can shift results by several points.
