02

What it tests

Alongside the public benchmarks, the GPT-3 paper built a handful of tasks from scratch to ask a narrower question: can the model learn a *new* skill from the examples in its prompt, rather than recall something from pre-training?

Arithmetic is the cleanest case. The 175B model got 100% on 2-digit addition and 98.9% on 2-digit subtraction few-shot, but fell to ~10% on 5-digit problems and 29% on 2-digit multiplication; smaller models were near zero. The authors checked for memorisation and found fewer than 0.8% of problems in the training data.

Word scrambling tests a similar thing with letters: 'inoffensive' from 'noffensive i'? The model managed reversed words only 0.4% of the time — a direct symptom of BPE tokenisation, which hides individual letters. SAT analogies (65% vs ~57% for college applicants) and the news-article Turing test (humans at 52% accuracy, barely above chance) rounded out the section.

None of these are downloadable benchmarks, but they shaped later evaluation design: GSM8K-style arithmetic, letter-level manipulation tasks in BIG-bench, and human-preference studies all descend from here.

3Score a model

Two helpers cover every benchmark in this collection: loglik for anything multiple-choice (score each option, pick the highest) and generate for anything free-form. Swap MODEL for whatever you are evaluating.

python · helpers
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

MODEL = "gpt2"                                   # or "Qwen/Qwen2.5-1.5B", "meta-llama/Llama-3.2-1B", …
tok = AutoTokenizer.from_pretrained(MODEL); model = AutoModelForCausalLM.from_pretrained(MODEL, torch_dtype=torch.bfloat16).eval().to("cuda")

@torch.no_grad()
def loglik(context, continuation):
    """Sum of log-probs of `continuation` tokens given `context` — the standard multiple-choice scorer."""
    ids = tok(context + continuation, return_tensors="pt").input_ids.to(model.device)
    n_ctx = len(tok(context).input_ids)
    logp = model(ids).logits.log_softmax(-1)[0, :-1]
    return logp.gather(1, ids[0, 1:, None])[n_ctx - 1:].sum().item()

@torch.no_grad()
def generate(prompt, max_new_tokens=32, stop=None):
    ids = tok(prompt, return_tensors="pt").input_ids.to(model.device)
    out = model.generate(ids, max_new_tokens=max_new_tokens, do_sample=False, pad_token_id=tok.eos_token_id)
    text = tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True)
    return text.split(stop)[0] if stop else text
python · evaluate
# Regenerate GPT-3's arithmetic probe: 2,000 random problems per sub-task, exact-match scoring
import random
def problems(digits, op, n=2000, seed=0):
    r = random.Random(seed); lo, hi = 10 ** (digits - 1), 10 ** digits - 1
    for _ in range(n):
        a, b = r.randint(lo, hi), r.randint(lo, hi)
        yield f"Q: What is {a} {&#x27;plus' if op == '+' else 'minus'} {b}?\nA:", str(a + b if op == '+' else a - b)
FEW = "Q: What is 48 plus 76?\nA: 124\n\nQ: What is 97 minus 29?\nA: 68\n\n"
for d in (2, 3, 4, 5):
    for op in "+-":
        ps = list(problems(d, op)); ok = sum(generate(FEW + q, max_new_tokens=8, stop="\n").strip() == a for q, a in ps)
        print(f"{d}-digit {op}: {ok / len(ps):.1%}")

07

Pitfalls

  • Results depend heavily on the number format (commas, spaces) and the tokeniser; compare models only under the same formatting.
  • Arithmetic 'accuracy' here is exact string match of the integer answer.
  • The news-detection study used 80 US participants — a small sample.
